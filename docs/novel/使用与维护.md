# Kazumi's book 使用与维护

本软件保留 Kazumi 的番剧功能，并增加轻小说书架、阅读器、跨源续读与 WebDAV 阅读数据同步。产品代码在 `feature/novel-reader`，`main` 保持上游镜像。

## 获取安装包

优先从[本仓库 Releases](https://github.com/ZGCC3890/Kazumi-s-book/releases)下载 Android APK 或 Windows ZIP。也可以打开[本仓库构建记录](https://github.com/ZGCC3890/Kazumi-s-book/actions/workflows/book-ci.yml)，选择产品分支最近一次成功构建，在 Artifacts 下载：

- `Kazumis-book-Android-development`：解压后安装 arm64 APK，适合 Android 手机和平板。应用标识是 `com.zgcc.kazumisbook`。
- `Kazumis-book-Windows-development`：解压 Artifacts 后再解压其中的程序 ZIP，保持目录完整，运行 `kazumis_book.exe`。

两者显示名称都是 **Kazumi's book**。Android 使用独立包名；Windows 使用独立产品名、数据目录和互斥量。0.1.0 起使用本应用自己的固定 Android 签名，以后沿用它覆盖升级。之前的 debug 开发包签名不同，需要先卸载旧开发包。长期签名私钥不进入仓库，通过仓库 Secret `BOOK_ANDROID_SIGNING` 提供。

操作验收使用 API 34 的 Android x86_64 release 模拟器包，覆盖手机与平板布局；交付的 arm64 APK 单独构建并校验证书，不能据此称 ARM64 真机操作已验。Windows 的逐项原生操作使用 Debug 集成测试，Release ZIP 另做构建、身份和启动检查；各步骤的具体结果见[操作验收表](0.1.2-操作验收表.md)。

## 搜索与开始阅读

主搜索页的搜索栏左侧可切换“番剧／小说”，默认搜索番剧，两种输入分别保留。小说按书名搜索已安装书源，结果显示为封面网格，书名位于封面下方。点击进入小说详情，再点击“选择书源阅读”。番剧与小说共用最近搜索，点击历史使用当前搜索类型；无痕模式不保存历史。番剧筛选和以图搜番仍仅用于番剧。

1. 点击爱心导航，默认进入“追番”，再点击标题旁的“书架”与“搜索小说”；也可直接点击番剧的阅读按钮。
2. 默认小说规则自动获取。各源同名或明确别名的结果汇总到一个详情入口，选源时仍展示各自书名和作者，不合并已有阅读档案。结果下方“书源状态”可查看登录、无结果、错误及重试。番剧搜索小说会去掉季／部分标记、成对波浪线副标题和“小说版”标记；如“辉夜姬想让人告白”可通过 Bangumi 的真实别名关联“辉夜大小姐想让我告白”，不使用 AI 自动兜底。
3. “追番”和“书架”在爱心页面内并列，手机底栏和平板／桌面侧栏维持原四项导航。书架以封面卡片网格展示，可设为默认启动页。试读不自动加入书架；读过两个不同章节后退出会询问，只加入小说书架，不修改番剧追番或观看状态；旧版已有书架记录保留。卡片菜单“删除书籍”确认后移出书架，保留阅读进度和书签；手动同步会传播删除，重新加入可续读。
4. 在书架菜单中选择“更换书源”，进入对应小说详情后选择目标书源续读，无需手动填写关联版本。
5. 书架和小说详情中，有对应番剧时显示电视图标“查看番剧详情”。已有小说关联直接使用；其余按作品名和 Bangumi 别名匹配。多个番剧条目会列出名称和年份供选择。查询失败可点错误图标重试，不影响阅读；跳转本身不修改小说关联或番剧收藏。搜索封面网格不逐本触发番剧关联查询。

默认提供 LightNovel 中文译文、轻之文库中文原创、文库8、小説家になろう四套规则。前两个源的公开章节支持匿名搜索和阅读；LightNovel 部分章节需站点权限，应用会明确显示限制，不把摘要或隐藏快照当作全文。两个站点分别来自 www.lightnovel.fun 与 www.linovel.net。

文库8站内搜索需要每台设备首次登录本人账号，应用在该源结果旁显示“首次登录”按钮，不打断其他源。会话按书源保存在本地，重启可继续使用；密码不保存，不参与 WebDAV 同步。会话过期或站点主动撤销时需要重新登录。有公开书籍地址时，也可在该源菜单选择“打开书籍链接”，粘贴例如 `https://www.wenku8.net/book/4343.htm` 的详情页链接直接读取，不需要搜索登录。

文库8搜索存在站点规定的 5 秒间隔。登录验证只请求首页，不消耗一次搜索；过快重搜会显示站点原始限制提示，不再显示“没有找到这本小说”。规则读取原始 HTML 的 `title` 属性，避免把网页脚本生成的 `tiptitle` 当作原始字段。

仓库内规则保存在 [`novel_rules/`](../../novel_rules/README.md)，与应用代码分开导入、更新和删除。规则变更不要求重新安装应用。自定义索引 URL 保存在本机；修改规则后对应目录、正文缓存按规则内容重新计算。连载更新时，在阅读页点击“刷新目录与正文”，重新取得目录和当前章内容并恢复阅读锚点；刷新失败会显示错误，点击重试会再次联网刷新。

“小说规则”默认显示已安装来源；点击“添加规则”，与番剧使用相同的方式选择“浏览规则仓库／从剪贴板导入／从文件导入”。仓库进入即加载，选择书源点“安装”即可；已安装来源可“重新获取”，不将已安装误称为有更新。仓库地址在右上角设置中修改，验证目录成功后才保存。剪贴板会预填内容，支持 HTTP 规则地址、共享规则链接、JSON 和 JSON 数组；仅接受小说规则，批次解析失败不写入，失败时保留表单供修改。已安装规则菜单可复制链接或确认删除。

已有规则可以立即搜索，已有小说直接进入阅读器；首次没有规则时才等待默认安装。旧默认规则升级独立执行，失败有提示和重试，不阻挡已安装来源。更新后仅重新搜索新增或变化的源，同 ID 旧请求不能覆盖新结果；下载期间的手动导入和删除按最新存储状态处理。

规则请求站点公开页面/API或本人本机会话，不内置共享账号。文库8此前的 Dart 403 经单变量实验证明与 Chrome UA、gzip 请求有关；规则改用应用 UA 与 identity 后，Dart 已取得 23 章、93 段正文、13 张有序插图及首张 JPEG。生产 Dio 会话链路另有实测记录。小説家になろう API 在本环境仍有 403，未宣称其正文联网验收完成。站点访问验证、429 限流等 HTTP 错误会直接显示；不会自动换代理或替换成其他来源。

## 阅读与跨源续读

支持滚动/左右翻页、目录、章内进度和章节拖动、字体字号、行距、页边距、日间纸色、阅读遮罩亮度、横竖屏及沉浸阅读。Windows 支持方向键、PageUp/PageDown 与空格翻页。插图按正文位置显示，点击可打开缩放视图。

阅读器明暗与应用“主题设置”一致，选择跟随系统时也随系统切换。深色模式使用应用深色背景、正文与控件配色；亮色模式恢复阅读设置中的纸白／护眼／羊皮纸。原独立“夜间”选项改为统一跟随应用，旧夜间偏好在亮色时按纸白显示。切换明暗不重新加载章节、不改变滚动位置或页码。

阅读时默认隐藏上下工具栏和章节提示，点击正文中间显示，再点击隐藏；长按仍可选择文字。平板实际滚动区域覆盖整个视口，左右留白也可上下拖动，正文保持居中限宽。

0.1.1 修正独立版错误继承私有镜像默认配置的问题：搜索与评论使用 Kazumi 原有的 Bangumi 官方直连路径，旧配置只迁移一次，可在网络设置自行选择。HTTP 失败显示实际错误，与真正没有搜索结果分开。弹幕接口保持弹弹play官方路径，独立应用凭据申请暂缓，当前未配置时明确提示不可用。

阅读位置自动写入本地；书签用于另外标记想再次阅读的位置。更换字号、窗口大小或阅读方式时按正文位置恢复，不把页码当作跨设备位置。外观设置按设备保存。

跨源续读先匹配章节，再核验正文锚点及插图位置。优先采用已有章节对应关系，或同卷同章号与标题；译名不同时仍可按同卷同章号定位。正文或插图位置不确定时自动从对应章节开头继续，并显示提示；只有章节无法唯一对应时才需要选章，对应关系会保存并同步。不同源缺章、拆合章时仍可能需要选章，不用目录数组序号猜位置。

## WebDAV 手动同步

在“设置 → 多设备同步”中配置自己的 WebDAV，启用总开关和小说同步，再点击“立即同步小说”；也可以在书架点击右上角“同步小说”。启用开关本身不执行同步。

阅读时持续保存到本地；启动、定时检查、修改、退出阅读以及前后台切换均不触发小说云同步。手动点击后才合并小说书架、作品关联、版本与书源绑定、阅读位置、人工章节映射和书签。规则文件、正文和图片缓存留在本机，不随 WebDAV 传输。并发修改会提示选择，不按设备时间或“最远进度”静默覆盖。

新设备首次搜索时会自动获取默认规则。非默认的自定义书源仍需由用户添加；默认安装只自动替换索引明确声明的旧版原文摘要，保留用户改写规则。用户主动删除规则后，不会在每次打开应用时重新强装。

Nextcloud 可把 WebDAV 基址指向 `/remote.php/dav/files/你的登录ID/指定目录/`。目录名含中文时原样填写中文和末尾 `/`，不要预先转成百分号编码；当前官方 `webdav_client` 的 MOVE 会再次编码地址。密码使用 Nextcloud“个人设置 → 安全 → 设备和会话”生成的应用密码。

同一个 WebDAV 地址可以在官方 Kazumi 与本应用使用。观看记录、收藏模型和同步流程沿用官方 2.3.9 基线；小说的新文件直接使用 `/kazumiSync/novels/`，官方按既有文件名读取与清理，不会同步或删除小说目录。小说进度只在支持小说的客户端之间同步，不能在官方界面阅读。

升级后自动读取旧 `novels/v1/` 数据，合并并上传到上述目录；只有新文件成功回读、校验并完整保留旧修订后，才逐文件删除被覆盖的旧快照。并发候选和删除书签的记录都保留在当前快照中，进度保存不再无限积累历史文件。同步中途失败会显示错误并保留有效数据。旧版设备仍会写入旧目录，因此请将支持小说的设备一起升级；程序不递归删除旧目录，也不清理其它设备尚未提交的 `.cache` 文件。

每台安装的设备身份由应用独立生成，不能把包含设备身份的应用数据目录克隆到另一台同时运行的设备；跨设备迁移使用 WebDAV。上传中止或失败后清理本次临时文件，下次同步也会识别并清理同一设备身份遗留的上传文件；已发布文件仍须按上述因果验证流程整理。

## 同步 Kazumi 上游更新

在产品分支提交当前修改后，从仓库目录运行：

```powershell
powershell -File dev/sync-upstream.ps1 -CheckOnly
powershell -File dev/sync-upstream.ps1
```

脚本将 `upstream/main` 合并到 `feature/novel-reader`，保留双方历史。遇到冲突时停在 Git 的合并状态，解决后提交；需要撤销本次合并时使用 `git merge --abort`。随后检查名称、应用标识、版本和更新地址，运行测试，推送产品分支触发 Android/Windows 构建。不要把产品改动合回用作上游镜像的 `main`。

应用检查更新只访问 `ZGCC3890/Kazumi-s-book` 的 Releases。先推送产品分支，由 `book-ci.yml` 完整测试并构建固定签名 Android APK 与 Windows ZIP；全部成功后给同一提交推送 `0.*` 版本标签，`book-release.yml` 校验提交与版本一致，直接发布该成功构建的产物及 SHA256SUMS，不重复打包。标签必须为纯数字版本（例如 `0.1.0`），与 `pubspec.yaml` 版本名一致，供现有更新比较器使用。上游发布工作流仅允许在 `Predidit/Kazumi` 运行，避免 fork 使用官方打包与签名流程。

Windows 从 0.1.2 起只提供 ZIP 更新选项，与本项目发行格式一致。已安装的 0.1.1 更新窗口仍默认显示旧的 MSIX 选项，第一次升级需在该窗口选择 ZIP，或从本仓库 Release 下载 ZIP；新版之后无需选择未提供的安装类型。

GitHub 的工作流邮件由账号通知偏好控制：打开[通知设置](https://github.com/settings/notifications)，在 System → Actions 的通知方式中取消 Email；需要保留站内通知时仅保留 On GitHub。此设置影响该账号的 Actions 通知，不会关闭仓库测试，也不改变失败状态。位置与方式参见 [GitHub 官方说明](https://docs.github.com/en/subscriptions-and-notifications/how-tos/managing-github-actions-notifications)。

实施状态与证据见[方案](Kazumi-轻小说实施方案.md)和[Astra 审查记录](Kazumi-架构审查记录.md)。
