# Kazumi's book 实施方案

状态：0.1.0测试版已发布，设备体验待用户验收（2026-10-17）。本轮完整286项测试、固定Android release签名/包名与Windows构建/原生启动检查通过。默认书源首次自动获取，首次本人登录会话仅保存在本机；官方观看/收藏同步协议兼容验收通过。文库8生产Dio已实际取得23章/93段/13插图及首图；真实Nextcloud快照交换闭环通过；小説家联网及实体设备交互仍待验收。本文是实施和验收的唯一计划入口，持续局部更新。架构师负责方案与审查，实施者负责代码与进度证据；分享对话中的历史建议不覆盖用户当前要求。

## 1. 目标与边界

在用户自己的 [ZGCC3890/Kazumi-s-book](https://github.com/ZGCC3890/Kazumi-s-book) 中增加轻小说规则、原生阅读器、追番卡片播放/阅读快捷入口、番剧详情阅读入口、本地自动阅读位置和 WebDAV 同步。追番卡片的按钮放在观看状态右侧，与截图指定的位置一致。阅读器仅提供阅读功能，不加入评论或弹幕。用户已指定首批真实书源为 `www.wenku8.cc` 和 `syosetu.com`，目标平台为 Android 与 Windows，必须与官方版共存。

产品定位已由用户明确为独立软件，名称精确为 **Kazumi's book**，仓库 slug 为 `Kazumi-s-book`。保留现有番剧能力并增加小说，不再以“定制版”作为产品名称或定位。

必须保留现有视频规则、播放流程、追番状态、视频历史和 WebDAV 数据兼容性。新增功能遇到规则失败、作品歧义、章节歧义或同步冲突时应展示具体原因和明确操作，不编造内容、不将空结果当成功、不静默跳到首章或近似章节。

“同一本小说跨源恢复”按用户最新要求：选择对应小说后直接阅读，内部身份不要求用户手动确认版本。章节确定时优先恢复可核实的文本位置；正文或插图位置不确定时自动从对应章节开头继续，仅章节无法唯一对应时让用户选章。不承诺不同译文有相同字符位置。

### 2.1 固定的模块落点和接口边界

- `lib/novel/novel_models.dart`：work/edition/binding、目录、内容块、位置/书签、带 schemaVersion 的 JSON 类型；纯 Dart，不引用 Widget 或 GStorage。
- `lib/novel/novel_rule.dart`：独立小说规则、请求和 HTML/XPath 提取，将站点输出转成统一文字/插图内容块。可复用低层网络设施，不能调用视频 queryChapterRoads 假装小说目录。
- `lib/novel/novel_locator.dart`：章节候选、规范化、文本锚点及明确匹配结果；纯函数便于测试。
- `lib/novel/novel_sync_state.dart`：修订向量、实体合并、冲突及 schema 迁移；纯 Dart 层不直接做 WebDAV 请求。
- 本地持久化：独立 Hive JSON box、串行读改写、设备标识/计数、变更通知。首版由 NovelService 封装，可在需要独立测试替身时抽取 repository；页面始终不直接访问 box。一次本地提交必须把数据及其修订一起持久化，不能让 counter 和正文分别落盘而重用修订。
- `lib/novel/novel_service.dart`：统一业务入口；搜索/绑定、获取目录正文、更新位置/书签、请求同步、解析与解决冲突。通过 `core_module.dart` 注册根作用域单例；页面状态仍归页面所有。
- `lib/novel/pages/`：书源管理、搜索/绑定、书架/记录、目录、阅读器、冲突选择；通过现有路由注册。动画卡片和详情传同一 BangumiItem 上下文进入。
- `lib/services/sync/webdav.dart`：仅新增小说的目录传输入口，沿用 `_runWebDavExclusive`、client、账号和连接初始化；不改旧视频/弹幕合并语义。
- `lib/pages/settings/sync/webdav_sync_page.dart` 与 `settings_keys.dart`：小说同步开关、状态和手动同步；主开关关闭应同时关闭小说子开关。

M1 批准的最小公开能力为：读取作品及关联、提交实际阅读位置、增删查书签、导出/合并同步状态、列出/解决冲突。具体 Dart 命名可按实现统一，但 UI 不得直接写 Hive 或自行实现同步合并。

### 2.2 分支维护和独立安装

`main` 保持 `upstream/main` 的官方镜像；本软件功能在 `feature/novel-reader` 维护并推送到 origin。后续在干净的产品分支直接运行 `./dev/sync-upstream.ps1 -CheckOnly` 检查官方更新，运行 `./dev/sync-upstream.ps1` 将最新 `upstream/main` 合入产品分支。脚本保留提交历史，不 reset、不 force push；fetch/merge 日志写入 `.git/book-upstream-sync.log`。发生冲突时保留合并现场，依据冲突内容解决并提交；需要取消该次合并时使用 `git merge --abort`。维护 main 时只做官方历史的快进同步，产品改动不混入 main。合并后重跑小说与既有视频回归，核对产品名称、包标识、数据目录及更新地址，再推送产品分支触发构建。

Android applicationId 为 `com.zgcc.kazumisbook`，应用名称为 `Kazumi's book`；Windows 必须使用独立可执行文件、窗口/互斥量、公司/产品名及安装标识，并验证应用支持目录也独立。仅换窗口标题不满足共存。现有官方签名者信息不可用于假装官方发布；打包使用用户可用的签名方式并如实记录。测试同时安装/运行官方 Kazumi 和 Kazumi's book，分别修改设置，确认不会覆盖安装、抢占运行实例或读写同一 Hive 数据目录。

本软件的应用更新源指向 `ZGCC3890/Kazumi-s-book`，避免日后获取官方安装包而丢失小说功能。`api_endpoints.dart` 当前官方 releases/latest 与初始化/引导页 AutoUpdater 调用链需要一并调整；fork 尚无 release 时显示真实状态，不改回官方源。官方项目署名、许可证及既有视频规则仓库不因此批量替换。

## 3. 领域边界与数据模型

### 3.1 作品身份

小说使用独立、持久的 `canonicalWorkId`，不能直接使用动画的 Bangumi ID。一个动画季可能改编同一小说的一部分；多个动画季可能对应同一本小说；同一系列也可能有主线、外传和不同原作。模型必须允许动画到小说的多对多关联。

建议拆成以下实体，字段名可按仓库惯例调整，但语义不能省略：

| 实体 | 必需信息 | 约束 |
| --- | --- | --- |
| NovelWork | 稳定 ID、规范标题、别名、作者、系列关系、可信外部标识及来源 | 标题只用于检索，不是唯一主键 |
| NovelEdition | work ID、语言、译本/出版版本标识及证据 | 不同译本不能自动等同文本位置 |
| AnimeNovelBinding | 动画 ID、work/edition ID、关系类型、确认来源 | 不把同名或同系列自动当原作 |
| NovelSourceBinding | 规则稳定 ID、规则版本、站点书籍 ID/规范 URL、work/edition ID、确认记录 | 切源更换 binding，不另造一本书的进度 |
| ReadingPosition | work/edition ID、源绑定、章节定位、文本锚点、会话及修订 | 每部小说一个当前位置，可主动倒退 |
| UserBookmark | 独立 ID、work/edition ID、章节及锚点、用户备注 | 手动添加，不能被自动阅读位置覆盖 |
| ReaderPreferences | 字号、行距、主题、模式及布局偏好 | 设备能力与用户偏好分开 |

从动画点“阅读”时，用去掉续作后缀的标题查询小说规则；紧凑弹窗展示各源候选，用户点选小说即建立关联并阅读，不再显示版本确认表单。已有小说切源承接同一内部身份和进度。动画没有明确对应小说时允许用户选择作品，不能拿搜索第一条作为事实。跨设备存在两个独立创建的 work ID 时不按名称静默合并。

### 3.2 章节及文本位置

目录节点保留原始标题、卷信息、章标题、可解析章号、序言/番外等章节类型、源内稳定 ID/URL和源内顺序。目录数组下标仅用于当前源导航，不能作为跨源身份。

阅读位置保存内容语义：章节标识、规范化文本的段落/字符偏移、当前位置前后短文本、锚点哈希及内容版本。插图作为原文顺序中的独立内容块，位置可指向具体插图或图文边界；不能把所有插图位置折叠成相同字符偏移。保存源内图片标识及邻接文本证据，跨源无法证明图片或段落位置时从已确定章节开头继续并提示。页码、滚动像素和百分比可以作为当前布局的显示结果，不能作为唯一恢复依据。页面字号、行距、屏幕大小或模式变化后，由同一内容锚点重新计算可见位置。

跨源恢复按明确证据分层：

1. 用户选中对应小说后建立或复用内部作品与阅读记录，不要求确认版本。
2. 优先使用已确认的章节映射，再核对卷、章节类型、章号和规范化标题；标题译名不同时允许同卷同章号匹配。
3. 在候选章节正文中匹配锚点及前后文。匹配必须唯一，且满足已定义的正文标准化规则；不因单个短句相同就确认。
4. 章节唯一但正文或插图位置未匹配时自动从该章开头继续并提示；同号不同卷、上下篇拆合、番外、重复标题导致章节无法唯一确定时才选章。缺章不自动跳到下一章。
5. 用户确认映射后保存证据。之后目录或正文发生变化时重新核实，不把失效映射继续当成准确恢复。

自动定位结果必须返回类型化状态：精确恢复、需要选择、目标缺章、正文变化、来源错误。不得用一个通用百分比把不同状态伪装成恢复成功。

## 4. 小说规则与内容管线

小说规则必须与视频规则在类型、存储、导入和执行入口上可区分；保留视频 schema 和历史规则行为。小说规则包含稳定 ID、schemaVersion、名称、域名、搜索请求、搜索项选择器、作品信息选择器、卷/章节目录选择器、章节正文选择器，以及明确声明的目录/正文分页规则。

规则维护遵从用户最新要求：规则与客户端应用分离维护，但不另建仓库。同一 fork 根目录 `novel_rules/` 保存独立规则文件和 `catalog.json`，默认目录索引为 `https://raw.githubusercontent.com/ZGCC3890/Kazumi-s-book/feature/novel-reader/novel_rules/catalog.json`。客户端提供独立规则导入、更新、删除，以及自定义索引 URL；不将另一份规则预载进 assets，不出现两处规则副本。索引包含规则稳定 ID、版本及下载地址；更新核验规则身份/版本后替换本地已安装规则，不能通过改名称另造 sourceId 而丢失绑定。目录下载失败应保留当前已安装规则并显示更新失败；不会假装已更新。

第一阶段以现有项目支持的 HTML/XPath 能力实现。规则不隐含执行任意脚本；是否支持 JS 站点必须由现有能力和用户需求决定。请求参数、字符编码、相对 URL、重定向后基准 URL、分页终点、正文段落/换行及插图应有固定语义。正文清理由规则显式声明；不能用全局“删除像广告的段落”猜测。

两个目标源分别验证：文库8的响应编码、卷标题与章节节点关系；小説家になろう的目录分页、短篇/连载差异和 ruby 注音处理。其[官方 API 文档](https://dev.syosetu.com/man/api/)提供 UTF-8 的作品搜索与元数据、稳定 ncode 和作者字段，输出可选 JSON；若接入 API，应在规则 schema 中显式声明搜索类型，不在失败后暗中切换抓取路线。正文及插图仍需实际页面解析证据。2026-10-17 的网页调研工具对 wenku8.cc 返回 403，该结果仅反映此访问路径，不能据此代替用户设备测试或猜写选择器。

用户偏好尽可能免登录访问公开内容。规则及应用不嵌入用户个人 Cookie，不把浏览器已登录会话当作匿名客户端可用的证据。匿名 Python 请求已证实文库8书籍 4343 的详情、目录、正文及首图 HTTP 200，但搜索最终跳转 `login.php`；捕获样本通过生产 adapter 解析，Dart HTTP 仍 403，实际应用联网阅读待验证。已提供用户明确选择的公开书籍 URL 添加入口，与搜索作为两种独立操作；不能在搜索失败后暗中切换路径。小説家になろう API 本环境仍为 403。

规则执行的每一步保留阶段名称和可展示的错误，区分 HTTP 错误、选择器错误、空匹配、无效 URL、正文为空和分页循环。开发验收分别检查搜索、目录、正文及插图结果；应用内交互式规则测试工具属于可选维护增强。至少有两个可复现的真实格式样本验证同书跨源；是否内置真实站点规则要依据站点实际可访问的页面确定，不能交付占位 URL 作为已完成规则集。

缓存是用户读取过的正文及其来源/版本的显式离线能力。缓存内容过期和联网失败需明确呈现，不能静默展示旧内容来掩盖规则错误。阅读页“刷新目录与正文”先保存位置，再强制取得新目录及当前章正文，并按语义锚点恢复；失败显示错误，错误页重试继续强制刷新。正文缓存可重新生成，不参加 WebDAV 阅读数据同步；已读位置和手动书签必须独立持久保存。

## 5. 阅读器与入口交互

| 功能 | 预期行为 | 必须覆盖的边界 |
| --- | --- | --- |
| 阅读模式 | 连续滚动、横向分页；模式偏好可保存 | 切模式仍保持原文本位置 |

| 主题 | 浅色、深色、护眼及跟随系统 | 正文、插图、目录和工具条对比度 |
| 插图 | 保持段落与图片在源正文中的原始顺序，点击放大并缩放 | 图片加载后不跳读；连续图片/纯插图章节位置可恢复 |
| 亮度 | 能力允许的平台调节，显示跟随系统选项 | 离开阅读器恢复进入前状态；不支持则明确标注 |
| 导航 | 目录、上一章/下一章、阅读进度、跳转及返回原位置 | 序言/番外、末章、目录更新 |

| 屏幕 | 横竖屏、窄屏/宽屏、平板最大行宽 | 重排恢复锚点，不保存无意义旧页码 |
| 桌面 | 键盘翻页/章节导航、鼠标滚轮、焦点和窗口缩放 | 输入框中快捷键不抢占输入 |
| 书签 | 添加、删除、列表跳转和备注 | 与自动位置分离；可返回当前阅读处 |

追番卡片播放按钮按用户要求每次直接打开选源界面，复用详情的 SourceSheet 流程；不先跳详情、不改为自动历史续播。选择来源之后沿用既有播放器路由及历史定位。阅读按钮使用统一小说入口；详情页也调用同一入口，避免两处产生不同绑定或进度。小屏状态行不足时调整间距/换行，但按钮必须可点击、具有语义标签，且不触发卡片本身导航。

## 6. 本地保存与 WebDAV 同步

### 6.1 本地保存

实际可见的文本位置变化时增量保存：分页提交翻页位置，滚动采用节流保存稳定可见的文本锚点；切章、退出阅读器、应用进入后台前提交当前位置。保存队列按会话顺序串行，较早的异步任务不能覆盖后来位置。测试明确断电/强制结束可能损失的最大窗口，不能只在退出页面时保存。

阅读位置允许用户主动返回早先章节，也允许重新阅读。不能把所有设备进度取最大，不能将“更靠后”当作“更新”。位置和手动书签均有本地修订信息；每次明确删除写入墓碑，不能只从列表消失。

### 6.2 同步协议

阅读数据使用独立的、带 schemaVersion 的 WebDAV 命名空间，避免旧版客户端重写原视频同步文件时抹掉小说字段。复用现有账号配置与连接能力，不改变视频同步语义。

源码核对后的固定方案是设备独立的不可变修订快照：`/kazumiSync/novels/v1/<deviceId>-<snapshotId>.json`。每次实际同步先读取已发布快照、逐实体合并到本地，再将需要发布的状态写到唯一 `.cache` 路径，成功后 MOVE 到此前不存在的最终 `.json` 路径。读者只读取最终文件；旧的有效快照不删除、不覆盖。没有本地或合并状态变化时不重复发布相同快照；本地每次保存不直接触发一次完整网络上传，采用有明确状态的合并调度。

选择这一方案的源码原因：现有 `WebDavRemoteFileCommitter.replaceFile` 上传临时文件后会先删除目标，再执行 rename，因此存在删除与 MOVE 之间的空窗，不应称为原子替换。小说不复用该方法的覆盖路径，不顺带修改旧同步协议。上线前通过故障注入验证 MOVE 失败时旧小说快照仍可读取；此项在验证前仅是已确认调用顺序带来的风险判断，不能冒充服务端实测结果。

初版保留不可变快照，远端占用随同步次数增长；仅传小体积阅读数据，不传正文缓存。后续垃圾回收需要单独协议和所有设备确认策略，不能擅自删除旧文件。自动同步应合并连续编辑，首次启用、前台恢复、退出阅读和手动同步都经同一个队列。设备 ID 从本机生成且不随 WebDAV 状态导入；设备计数也不被远端快照重置。不同设备最终一致，不承诺一次网络交错即彼此读到全部最新修改。

不可变快照必须增量读取：本地记录已经校验并成功合并的远端文件名，只 GET 新文件；已读标记在合并状态持久化成功后提交。该记录的作用域包含 WebDAV 服务地址、用户和目录，切换连接时重新建立对应域。失败下载/校验/合并的文件不标记成功。协议测试要求首次 N 文件产生 N 次 GET、未变化的第二次同步为 0 次 GET、增加一个快照只产生一次 GET，避免每次轮询重下全部历史。

实体修订必须能判断因果先后，例如每设备单调计数的修订向量。墙钟时间只用于展示，不能解决时钟漂移下的覆盖次序。不同实体直接合并；同一实体的后继修订替换祖先；互不包含的并发阅读位置保留两个候选，用户选择后生成包含双方修订的新记录。普通编辑和自动保存不能代替显式解决冲突，不得自动吸收所有候选后覆盖。阅读位置的选择展示设备、章节、上下文和记录时间。

书签、动画关联、源绑定和章节映射采用实体级记录，减少无关改动互相冲突。字体、字号、行距、主题、页边距和亮度按设备本地保存，适应手机与桌面的不同屏幕；方向由当前阅读会话控制，离开阅读页时恢复系统策略。用户要求的云同步范围是作品关联、阅读位置、书签及准确恢复所需的映射数据。删除墓碑与修改发生并发时必须显式解决，不能让旧设备无提示复活已删记录。初版保留墓碑，不引入无法证明所有设备已确认的自动清理。同步失败不清除本地修改，UI 显示未同步状态；重试只在相同协议中进行，不切换覆盖策略。

旧版阅读 schema 通过明确的逐版本迁移读取。未知未来 schema 应终止写入并告知版本不兼容。原有视频 WebDAV 文件的导入和导出回归测试必须继续通过。WebDAV 不同步正文缓存和设备能力状态。
